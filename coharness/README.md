# CoHarness 页面预览

这一版页面可以打开本地项目目录。页面展示修改地图、文件内容、代码对比、调用上下文和修改对齐。CoHarness 自身的源码也可以作为工作区。

开发者在项目根目录启动本地服务：

```bash
python3 coharness/server.py --port 8765
```

用户打开 <http://127.0.0.1:8765>。

服务默认打开启动目录。开发者可以通过 `--workspace /path/to/project` 指定工作区。用户也可以通过页面的“打开目录”切换工作区。

## 三个空间分别组织阅读、开发和审阅

项目空间提供“项目阅读”和“文件浏览”两个视图。项目阅读从场景进入流程步骤。每一步分别展示预期行为、运行证据和实现依据。依据面板支持调宽、全屏和原位置返回。

阅读路线必须来自当前项目的模型生成结果。产品不再加载预填的项目 JSON。页面只保留通用结构：项目用途、场景、步骤、预期和来源。

后端从工作区 KV 的 `reading:generated` 读取模型生成记录。记录使用 schema 1，并绑定 workspaceId。来源记录文件路径、行号和 SHA-256 内容版本。文件变化后，页面提示重新核对，并停止展示旧行号对应的当前代码。没有生成记录时，页面显示空状态。

模型后端连接仍待配置。场景执行器尚未接入。运行准备仅展示命令、环境要求和影响范围。模型生成的预期保持“未验证”，模型输出不能充当运行证据。

- 项目空间按照项目、目录和文件组织阅读。左栏只展示当前目录的直接子项。用户通过“返回上级”逐层导航。
- 目录页面展示本层组成，并引用该目录 README 的首段正文。缺少说明时，页面标记职责待补充。
- 直属文件超过 10 个时，页面默认收起文件列表。左栏展示前 100 个文件，项目搜索可以缩小范围。
- 文件页面通过面包屑返回所属目录。空间切换保留选中的目录。
- 目录索引保留全部可见文件路径。左栏使用单行文件名，支持调整宽度和项目搜索。
- 模型生成的职责说明和跨目录关联尚未接入。
- 开发空间展示当前需求。侧栏提供当前任务与暂存任务。
- 审阅空间展示当前修改或历史提交。侧栏提供版本选择和修改文件。
- 页面顶部仅保留空间切换、项目名称、打开目录和刷新。
- 同一页面中的空间切换会保留文件、修改项、输入草稿和滚动位置。
- 项目空间和审阅空间通过“在开发空间编辑”连接文件编辑。
- 开发空间通过“进入审阅空间”连接当前修改。

Git 状态提供修改提示。文件变化不会自动切换用户所在的空间。首次进入审阅空间时，系统优先打开当前修改；工作区干净时，系统打开最近提交。用户也可以手动选择当前修改或提交历史。

提交审阅复用修改项、调用上下文和对齐入口。系统将提交与第一父提交比较。首次提交与空目录比较。系统单独保存每个提交的审阅记录。提交审阅不会切换工作区版本。

系统按目录保存需求和预期草稿。用户进入开发空间后，可以继续该项目的当前任务。输入内容先保存到浏览器，随后同步到本地服务。

系统使用真实 Git 状态判断修改。换行转换和无法预览的文件不会产生虚假修改。修改地图优先预载变动文件。整批预载仍保留 1000 个文件和 8 MiB 正文上限。项目空间通过独立接口按需读取正文，因此预载额度不会阻止文件阅读。审阅空间的批量差异仍受预载限制。

## 用户暂存和恢复任务

用户在开发空间选择“暂存当前任务”。页面先展示操作范围。

工作区干净时，系统只暂存任务记录。存在修改时，系统使用 `git stash push --include-untracked` 暂存代码。新建文件进入暂存，忽略文件保留在工作区。代码暂存要求用户打开已有提交的仓库根目录。未保存的编辑内容需要先保存为工作快照。

开发空间的“暂存任务”列出可恢复的任务。恢复要求工作区干净，且没有其他当前任务。系统使用稳定对象编号执行 `git stash apply --index`，恢复原暂存区与工作目录修改。系统始终保留 Git 暂存备份。恢复失败时，系统显示错误并保留任务关联。

暂存不会改变 HEAD，也不会表示修改已对齐。外部工具移除暂存后，系统保留任务记录并报告缺失。暂存过程中发生中断时，记录会保留操作阶段和暂存消息，供人工检查。本版尚未提供自动修复入口或备份清理入口。

当前入口保存需求，尚未调用模型执行任务。DeepSeek 执行循环和对齐后提交仍在后续范围内。

## 用户逐层阅读修改

1. 用户通过目录选择文件。
2. 用户通过修改项查看实际代码差异。
3. 用户打开调用上下文。
4. 用户拖动面板边缘调整宽度。
5. 用户通过全屏按钮放大上下文。
6. 用户逐层展开调用者和被调用者。页面持续高亮阅读主角。
7. 用户通过“查看代码”打开临时查看层。
8. 用户通过顶部的“返回修改审阅”恢复阅读位置。页面保留原标签和草稿。
9. 用户提交预期修改效果。

## 系统保存本地记录

服务使用 SQLite 的 KV 表保存文件快照与对齐记录。服务按工作区标识分开保存数据库。默认路径为 `.coharness/workspaces/<工作区标识>.sqlite3`。Git 忽略该目录。

系统使用文件内容哈希标识版本。系统同时绑定本轮文件集合的快照，保守处理相关文件变化。用户刷新地图后，旧快照中的记录显示为待重新对齐。系统保留历史预期。保存时，系统检查源文件版本；旧页面无法给新版本写入确认。

系统从 Git HEAD 读取修改前内容。新增文件和删除文件使用单栏代码区。服务遵循 Git 忽略规则。服务只读取所选工作区范围内的文件。项目空间将超过 512 KiB 的 UTF-8 文本按不超过 128 KiB 分段读取。用户通过“上一段”和“下一段”翻页。行号从当前片段起算。系统检查分段版本，文件变化后要求重新读取首段。二进制和非 UTF-8 文件显示明确说明。改名尚未配对展示。

用户可以编辑不超过 512 KiB 的完整文本文件并保存工作快照。保存时，服务检查文件版本。工作快照不会创建 Git 提交。没有 Git 的目录会初始化本地仓库，初始化不会创建提交。当前页面尚未提供 Git 提交入口。

开发者可以将当前版本提交为后续修改的基准。提交后，已提交文件会显示为未修改。后续代码变化会出现在修改地图中。

## 页面注明数据依据

- 文件内容和差异来自真实本地文件。
- 文件说明来自首部注释或文档标题。系统尚未生成模型职责说明和修改目的。
- Python 定义定位使用 AST。JavaScript 定义定位使用顶层命名函数规则。
- 调用关系来自同文件词法候选，可能遗漏别名、回调、跨文件调用和动态调用，也可能误识别注释或字符串。
- 参数个数来自函数声明，可变参数计为一项。复杂 JavaScript 声明可能显示为待解析。
- 参数、返回和异常展示引用实际源码。页面尚不解析运行时值与完整数据流。
- 逐步演示用于定位阅读步骤。它不是代码执行轨迹。
- 对齐区保存人工输入与确认。系统尚未接入模型分析，实际效果保持待验证。
- 操作记录从服务首次观察文件时开始。服务未捕获此前编辑工具的操作。
- 页面内置跳转适配层。系统尚未接入外部编辑器跳转插件。
- 当前版本尚未安装到 DeepSeek Harness。

开发者运行行为检查：

```bash
python3 -m unittest discover -s coharness -p 'test_*.py' -v
```

开发者检查目录阅读的数据边界：

```bash
node coharness/test_spaces.cjs
```
