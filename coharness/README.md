# CoHarness 页面预览

这一版页面可以打开本地项目目录。页面展示修改地图、文件内容、代码对比、调用上下文和修改对齐。CoHarness 自身的源码也可以作为工作区。

开发者在项目根目录启动本地服务：

```bash
python3 coharness/server.py --port 8765
```

用户打开 <http://127.0.0.1:8765>。

服务默认打开启动目录。开发者可以通过 `--workspace /path/to/project` 指定工作区。用户也可以通过页面的“打开目录”切换工作区。

## 用户逐层阅读修改

1. 用户通过目录选择文件。
2. 用户通过修改项查看实际代码差异。
3. 用户打开调用上下文。
4. 用户拖动面板边缘调整宽度。
5. 用户通过全屏按钮放大上下文。
6. 用户逐层展开调用者和被调用者。页面持续高亮阅读主角。
7. 用户通过“查看代码”打开临时查看层。
8. 用户通过顶部的“返回修改审阅”恢复阅读位置。页面保留原标签和草稿。
9. 用户提交预期修改效果。

## 系统保存本地记录

服务使用 SQLite 的 KV 表保存文件快照与对齐记录。服务按工作区标识分开保存数据库。默认路径为 `.coharness/workspaces/<工作区标识>.sqlite3`。Git 忽略该目录。

系统使用文件内容哈希标识版本。系统同时绑定本轮文件集合的快照，保守处理相关文件变化。用户刷新地图后，旧快照中的记录显示为待重新对齐。系统保留历史预期。保存时，系统检查源文件版本；旧页面无法给新版本写入确认。

系统从 Git HEAD 读取修改前内容。新增文件和删除文件使用单栏代码区。服务遵循 Git 忽略规则。服务只读取所选工作区范围内的文件。二进制文件和大文件仅展示信息，改名尚未配对展示。

用户可以编辑文本文件并保存工作快照。保存时，服务检查文件版本。工作快照不会创建 Git 提交。没有 Git 的目录会初始化本地仓库，初始化不会创建提交。当前页面尚未提供 Git 提交入口。

开发者可以将当前版本提交为后续修改的基准。提交后，已提交文件会显示为未修改。后续代码变化会出现在修改地图中。

## 页面注明数据依据

- 文件内容和差异来自真实本地文件。
- 文件说明来自首部注释或文档标题。系统尚未生成模型职责说明和修改目的。
- Python 定义定位使用 AST。JavaScript 定义定位使用顶层命名函数规则。
- 调用关系来自同文件词法候选，可能遗漏别名、回调、跨文件调用和动态调用，也可能误识别注释或字符串。
- 参数个数来自函数声明，可变参数计为一项。复杂 JavaScript 声明可能显示为待解析。
- 参数、返回和异常展示引用实际源码。页面尚不解析运行时值与完整数据流。
- 逐步演示用于定位阅读步骤。它不是代码执行轨迹。
- 对齐区保存人工输入与确认。系统尚未接入模型分析，实际效果保持待验证。
- 操作记录从服务首次观察文件时开始。服务未捕获此前编辑工具的操作。
- 页面内置跳转适配层。系统尚未接入外部编辑器跳转插件。
- 当前版本尚未安装到 DeepSeek Harness。

开发者运行行为检查：

```bash
python3 -m unittest discover -s coharness -p 'test_*.py' -v
```
